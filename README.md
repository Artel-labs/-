# Сайт Центра ДПО факультета права НИУ ВШЭ

Новая версия сайта Центра дополнительного профессионального образования. Переписывается с нуля
на готовых фреймворках вместо самописного кода прежней версии
([itspecR/dpo-pravo-hse](https://github.com/itspecR/dpo-pravo-hse)). Дизайн сохраняется.

## Стек

| Часть | Технологии |
|---|---|
| Публичный сайт | Astro (страницы собираются на сервере из данных Django, без JS по умолчанию), TypeScript |
| Сервер | Django 5.2 LTS, django-ninja (API), gunicorn |
| Админка | Django Admin с темой Unfold, защита от подбора пароля django-axes |
| База данных | MariaDB 11.8 (в контейнере) |
| Веб-сервер | nginx: раздаёт шрифты, картинки и файлы, кэширует страницы на 60 секунд, проксирует `/api/`, `/admin/`, `/static/` |
| Развёртывание | Docker Compose, скрипты в `scripts/` |
| Проверки | pytest, ruff, mypy (strict), ESLint, astro check, shellcheck, GitHub Actions |

```
браузер ──► nginx (web) ──► страницы: Node.js + Astro (site) ──┐
                 │                                              ▼
                 └─► /api/, /admin/, /static/ ──► gunicorn + Django (app) ──► MariaDB (db)
```

## Структура

```
backend/            Django: config (настройки, API), core (служебное), accounts (пользователи),
                    catalog (каталог программ, начальные данные в catalog/seed), locale (переводы), tests
frontend/           Astro: страницы, макеты, стили и шрифты
deploy/             Dockerfile для app и для site + web (общая сборка Astro), конфигурация nginx
scripts/            установка, обновление, резервные копии, HTTPS
docker-compose.yml  пять контейнеров: db, app, worker (фоновые задачи), site (страницы), web
```

## Установка на сервер

Нужен сервер с Ubuntu 24.04 (или новее), доступ по SSH с правами sudo, свободные порты 80 и 443.
Скрипт сам поставит Docker, если его нет.

1. Склонируйте репозиторий. Он приватный, поэтому серверу нужен ключ доступа только на чтение (deploy key):

   ```bash
   ssh-keygen -t ed25519 -N "" -f ~/.ssh/dpo_deploy
   cat ~/.ssh/dpo_deploy.pub
   ```

   Добавьте показанный ключ в GitHub: репозиторий → Settings → Deploy keys → Add deploy key
   (галочку «Allow write access» не ставьте). Затем:

   ```bash
   GIT_SSH_COMMAND="ssh -i ~/.ssh/dpo_deploy" git clone git@github.com:itspecR/dpo-pravo-hse-v2.git ~/dpo
   cd ~/dpo
   git config core.sshCommand "ssh -i ~/.ssh/dpo_deploy"
   ```

2. Запустите установку — одна команда, вопросов она не задаёт:

   ```bash
   sudo ./scripts/install.sh
   ```

   Скрипт сделает всё по шагам:
   - поставит пакеты;
   - выберет свободные порты: 80/443, а если они заняты другим сайтом — 8080/8443, 8081/8444 и т. д.;
   - создаст `.env` со случайными паролями (файл доступен только владельцу);
   - скачает образы и соберёт контейнеры (при сбоях сети повторит попытку сам), применит миграции;
   - создаст администратора `admin` со случайным паролем и **один раз покажет пароль** — сохраните его;
   - включит ежедневную резервную копию;
   - включит HTTPS с самоподписанным сертификатом.

3. Откройте адрес, который скрипт напишет в конце, например `https://<IP сервера>/` или
   `https://<IP сервера>:8443/`. Браузер один раз предупредит о сертификате. Админка — `/admin/`.

Порты можно задать и вручную: `sudo env HTTP_PORT=8080 HTTPS_PORT=8443 ./scripts/install.sh`.
Только HTTP, без сертификата: `sudo ./scripts/install.sh --http`. Повторный запуск безопасен:
`.env`, база и администратор сохраняются.

Если группа `docker` была добавлена только что, перезайдите по SSH: после этого скрипты обновления
работают без `sudo`.

## Обновление

```bash
./scripts/update.sh          # ветка main
./scripts/deploy.sh <ветка>  # любая ветка
```

Порядок: получить код → собрать контейнеры → резервная копия базы → миграции → запуск → проверка
`/api/health`. Если любой шаг упал, скрипт вернёт прошлую версию кода и подскажет команду
восстановления базы.

## HTTPS

```bash
sudo ./scripts/setup-https.sh [домен-или-IP ...]
```

Создаёт самоподписанный сертификат в `/etc/dpo/tls`, включает защищённые cookie, записывает
адрес сайта в `SITE_URL` (первый указанный домен или IP сервера) и перезапускает сайт. Сертификат Let's Encrypt для настоящего домена будет добавлен отдельным шагом, когда домен
будет известен.

## Каталог программ

Каталог правится в админке: «Каталог программ» → «Программы», «Направления», «Преподаватели».
У программы есть вкладки: основное, условия, описание, объявление, а также программа обучения,
преподаватели, документы, частые вопросы и отзывы. Списки вроде «Кому подойдёт» заполняются
по одному пункту на строку. Порядок модулей, документов и других элементов меняется перетаскиванием.

При первой установке каталог заполняется данными прежнего сайта (34 программы с обложками,
фото преподавателей и PDF). Повторно это не происходит: правки в админке не перезаписываются.

### Обновление с hse.ru

Каталог каждый день в 04:00 по Москве обновляется со страницы
[программ факультета на hse.ru](https://www.hse.ru/edu/dpo/?orgUnit=22753). Запустить вручную —
кнопка «Обновить с hse.ru» в списке программ или `docker compose exec app python manage.py sync_catalog`.

- Новые программы на hse.ru добавляются и попадают в направление по названию.
- У остальных обновляются название, формат, даты, цены и описание со страницы программы; если
  какого-то блока на hse.ru нет, прежний текст сохраняется.
- Программы с галочкой «Не обновлять с hse.ru» не меняются вовсе.
- Программы, которых больше нет на hse.ru, скрываются с сайта (не удаляются).
- Скачиваются недостающие обложки и фото преподавателей, расписания обновляются каждый раз.

Время и история запусков — в админке, раздел «Фоновые задачи»: «Запланированные задачи»,
«Успешные задачи» (там же итог: сколько добавлено, обновлено, скрыто, что не удалось), «Неудачные задачи».

### Главная страница

Меню «Сферы права», карточки направлений, лента ближайших стартов, форматы обучения, популярные
программы, преподаватели и отзывы собираются из каталога при запросе (`GET /api/catalog/landing`):
правки в админке появляются на главной так же, как на страницах программ. Популярные программы —
пять отобранных вручную (список в `backend/catalog/presentation/landing/top.py`), дальше ближайшие
по дате старта. Девизы первого экрана — в `frontend/src/data/slogans.json`; после правки списка
увеличьте `version`, чтобы посетители начали новый круг фраз.

### Страница каталога

Каталог — `/catalog` (старые адреса `/Каталог программ.html` и `/catalog.html` перенаправляются,
параметры фильтра сохраняются). Порядок «по каталогу» — как в списке на hse.ru, программы,
добавленные вручную, идут в конце; порядок можно поправить в карточке программы, поле «Порядок в каталоге».
Фильтры, поиск, сортировка и сравнение до трёх программ работают в браузере; ссылки вида
`/catalog?sphere=digital&type=ПК&sort=start&q=право&compare=1,2` открывают каталог с нужным выбором.

### Страницы программ

Адрес страницы — `/programs/<название-латиницей>-<id>.html`, как на прежнем сайте. Если название
программы поменялось, старый адрес постоянно (301) перенаправляет на новый.

Изменения в админке появляются на сайте не позже чем через минуту: страницы собираются из базы
при запросе, nginx держит готовую страницу 60 секунд. Если сервис страниц временно не отвечает,
посетители видят последнюю сохранённую версию.

## Резервные копии

- Каждый день в 03:00 по Москве (таймер systemd `dpo-backup`). Копия — это два файла: база
  (`dpo-<дата>.sql.gz`) и загруженные файлы сайта (`dpo-<дата>.media.tar.gz`). Хранятся последние
  `BACKUP_KEEP` копий в `BACKUP_DIR` (по умолчанию 30 штук в `/var/backups/dpo`).
- Вручную: `sudo ./scripts/backup.sh`.
- Восстановление: `sudo ./scripts/restore.sh` покажет список копий,
  `sudo ./scripts/restore.sh <файл .sql.gz>` восстановит базу и файлы сайта (перед этим сохранит текущие).
- Таймер: `sudo ./scripts/backup-timer.sh status|install|remove`.

## Администраторы

- Первый администратор `admin` создаётся при установке, пароль показывается один раз.
- Забыли пароль или нужен новый: `./scripts/reset-admin-password.sh [логин]` — покажет новый случайный пароль
  и снимет блокировку входа.
- Других администраторов добавляйте в админке: «Пользователи» → «Добавить». Пароль — не короче 12 символов.
- После 5 неверных попыток пара «логин + адрес» блокируется на 15 минут.
- Снять все блокировки: `docker compose exec app python manage.py axes_reset`.

## Настройки (`.env`)

| Переменная | Назначение |
|---|---|
| `DJANGO_SECRET_KEY` | секретный ключ Django, создаётся при установке |
| `DJANGO_DEBUG` | `1` только для разработки |
| `DJANGO_ALLOWED_HOSTS` | адреса и домены сайта через запятую |
| `COOKIE_SECURE` | `1` при работе по HTTPS |
| `SITE_URL` | адрес сайта для канонических ссылок и разметки для поисковиков, например `https://example.com` |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | база MariaDB |
| `DB_ROOT_PASSWORD` | пароль root MariaDB, создаётся при установке |
| `HTTP_PORT`, `HTTPS_PORT` | внешние порты nginx |
| `TLS_DIR` | папка с сертификатом |
| `BACKUP_DIR`, `BACKUP_KEEP` | куда и сколько копий хранить |

## Разработка

Сервер (нужны Python 3.12 и MariaDB):

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
export DJANGO_SECRET_KEY=dev DB_HOST=127.0.0.1 DB_USER=root DB_PASSWORD=<пароль>
.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/mypy && .venv/bin/pytest
```

Сайт (нужен Node.js 24):

```bash
cd frontend && npm ci
npm run lint && npm test && npm run build
npm run dev   # http://127.0.0.1:4321, данные берутся из Django :8000 (переменная API_URL)
```

Все проверки повторяются в GitHub Actions (`.github/workflows/ci.yml`), включая полную установку
`install.sh` на чистой машине, резервную копию и восстановление.
